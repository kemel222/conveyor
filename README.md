# Конвейер учебных инженерных работ

Старый проект (`tools/`, `project-rules/`) не тронут. Этот конвейер лежит отдельно и не использует его код.

## Принцип
Шаги задаёт код, а не модель. Модель выполняет только узкую задачу и не проверяет сама себя.

| Шаг | Кто делает | Кто проверяет |
|---|---|---|
| Данные варианта (табл. 1.1 хрестоматии) | код `tasks/water_sprinkler/variants.py` | — |
| Нормы СП 5 (табл. 5.1, 5.2, прил. Б, В.2), паспорт оросителя, УУ «Шалтан», насосы | данные `norms.py` (сверены с СП 5 вручную) | — |
| Гидравлика по методике хрестоматии | код `hydraulics.py` | тест `tests/test_hydraulics.py` на примере хрестоматии (76,872 л/с; 50,96 м) |
| Текст разделов (введение, теория, выводы) | Sol через `codex exec` (`core/llm.py`, `prose.py`) | `check_prose.py`: объём, числа только из модели, запрещённые слова |
| DOCX/PDF: структура п. 1.2, формулы OMML, таблицы, рисунки | код `report.py`, `figures.py`, LibreOffice | `check_report.py` (бракует старые V3/V4: `tests/test_check_report.py`) |
| Чертежи: генератор листов | GPT-6 Astra через `codex exec` (`cad.py`), только в своей папке | `core/cad_check.py` + печать AutoCAD (`core/cad_plot.py`) |

## Запуск
```
cd conveyor
python -X utf8 run.py "<папка заказа>" --variants 3 4            # всё
python -X utf8 run.py "<папка заказа>" --variants 3 --only text  # только записка
python -X utf8 run.py "<папка заказа>" --variants 3 --reuse      # продолжить с принятых текста/генератора
python -X utf8 -m unittest discover -s tests -t .                # тесты
```
В папке заказа нужен DOCX хрестоматии и `order.json` (ФИО, группа, преподаватель, организация).
Результат: `<заказ>/Выдача/Вариант_N/`, ZIP и `SHA256.json`. Журнал: `<заказ>/_conveyor/run.log`.
Тестовый заказ: `_trial/Водяное пожаротушение — тест/`. Черновые скрипты: `_scratch/`, их можно удалить.


## Где конвейер тратит время

Оценки ниже относятся к одному варианту на локальной машине и включают только кодовые ограничения. Фактическое время зависит от очереди модели, LibreOffice и AutoCAD.

| Участок | Обычно | Жёсткий предел/масштаб | Что может задержать |
|---|---:|---:|---|
| Чтение варианта и гидравлическая модель | секунды | секунды | перебор сеток диаметров и рядков, ошибка исходных данных |
| Один вызов Sol для текста | 2,5–7 мин | 15 мин | очередь/503, большой JSON, отклонение разделов |
| Текст целиком | 5–15 мин | до 60 мин на 4 попытки | каждая отклонённая попытка переписывает только непринятые разделы, но занимает новый вызов |
| Сборка DOCX/PDF | 1–3 мин | до 12 мин на 3 прохода конвертации | LibreOffice, профиль во временной папке, пересчёт содержания |
| Один раунд Astra CAD | минуты | 30 мин + остановка после 8 мин без активности | очередь модели, 503, `Selected model is at capacity`, ручные правки генератора |
| CAD-итерации | 1–3 раунда | до 90 мин | замечания по DXF повторяют весь раунд |
| Запуск `generate.py` и проверки | секунды | 3 мин на раунд | зависший генератор или неверный DXF |
| AutoCAD-плот одного листа | секунды–минуты | 5 мин | запуск AutoCAD, занятый COM, отсутствие `DWG To PDF.pc3`, неверный формат A3 |
| Три AutoCAD-листа | минуты | до 15 мин | каждый лист печатается отдельно и проверяется повторно |
| Упаковка ZIP и SHA-256 | секунды | обычно менее минуты | заблокированный файл или кириллица в пути |

При штатных ответах моделей один вариант обычно укладывается примерно в 10–30 минут. При четырёх отклонённых текстовых попытках, трёх раундах CAD и задержках AutoCAD верхняя граница становится часами; это ограничение внешних исполнителей, а не расчётной части.

## Рабочие нюансы

- `--reuse` переиспользует принятый текст и существующий генератор, но `generate.py` всё равно запускается заново и проходит проверки.
- Одновременные запуски одной папки заказа не защищены блокировкой. Их нельзя запускать параллельно: процессы могут перезаписать `model.json`, `prose.json`, журналы и выдачу.
- Ответ Astra может не прийти из-за очереди или лимита сервиса. Bounded-run завершает такой раунд с ошибкой и не выдаёт частичный чертёж.
- Диагностический PNG не заменяет PDF-плот из того же DXF. Для выпуска нужен AutoCAD/DWG To PDF и проверка размера A3.
- Внешний исполнитель работает только в своей папке CAD; изменение `sheet_data.json`, `core/` или `tasks/` отклоняется.
- Пропущенные персональные данные в `order.json` не заполняются автоматически: их нужно указать до запуска.
- Путь с пробелами и кириллицей поддерживается, но сторонние COM/LibreOffice могут зависеть от локального профиля и прав пользователя.
- Архив исходников не содержит кэши, старые выдачи и временные журналы; smoke-материалы хранятся отдельно в `_scratch/astra_smoke`.
- GitHub push требует реального адреса репозитория и авторизации владельца. Секретный ключ нельзя придумывать и публиковать в README или архиве.

## Состояние конвейера
- Готово и проверено: гидравлика (эталонный тест), вызов Sol, проверка записки на старых V3/V4,
  печать пробного листа через AutoCAD COM (А3, `DWG To PDF.pc3`).
- Все 14 тестов проходят, включая `test_all_room_variants_solve` и регрессию маршрута Astra.
- Текст V3 принят проверкой по всем 9 разделам (`_trial/.../_conveyor/V3/prose.json`), повторный прогон
  `--only text --reuse` собирает записку без вызова Sol за 6 с.
- Ранее найденная проблема с малоплотной страницей V3 зафиксирована в истории отладки; текущий smoke-прогон проверяет только код маршрута и не запускает реальный заказ.
- `package()` (ZIP + `SHA256.json`) проверен офлайн на тестовых файлах, в т. ч. с кириллицей в путях.
- CAD-этап запускается через Codex `gpt-6-astra` с `model_reasoning_effort=high`; внешний Antigravity/Gemini из маршрута удалён.
- Полный прогон реального заказа намеренно не выполняется: он может занять несколько часов. Для быстрой проверки используется изолированный smoke-тест.

## Закрытые проблемы
Статус «закрыто» – исправлено и подтверждено тестом или прогоном; «исправлено, не подтверждено» – правка
сделана, но успешного прогона после неё ещё не было.

Из разбора старого конвейера (заказы V3/V4 от 2026-10-10) – закрыто устройством нового конвейера:
- Исполнитель сам писал «доказательства» и закрывал этапы (`finish_report.py` и т. п.). Здесь проверки –
  только функции кода, исполнитель их не вызывает и результат не подписывает.
- Внешний исполнитель вписывал константы «0 коллизий» в собственный preflight. Здесь `cad.py` сам перезапускает
  `generate.py` и проверяет DXF/PDF; изменение `sheet_data.json` или файлов `core/` и `tasks/` отклоняет результат.
- Пороги проверки записки задавал автор записки (`report-contract-V3.json`). Здесь пороги – константы в
  `check_report.py`.
- Напор насоса считался с двойным учётом потерь ветви (V3: 56,1 м, V4: 14,75 м). Формула
  Нтр = H1 + ΣΔH + 0,2·ΣΔH + Hуу + Z по хрестоматии; закрыто тестом на её примере (50,96 м).
- Отсутствовали потери в узле управления Hуу. Считаются по ξ узла «Шалтан» (Hуу = ξ·γ·Q²).
- Коэффициент запаса 1,15, которого нет в методике. Убран.
- Выдуманное «расхождение единиц» k в паспорте. Единицы описаны в `norms.py`, есть тест `test_passport_k_matches_sp5_form`.
- Объём набивался таблицами по каждому оросителю и приложениями (V3: 20 из 27 стр.). Проверка бракует
  таблицы длиннее 40 строк, приложения более 15 % объёма, служебные фразы; закрыто тестом `test_check_report.py`.
- Номера страниц в содержании подгонялись. Ставятся по фактическому PDF, проверка сверяет их.

Найдено и исправлено при отладке нового конвейера:
- LibreOffice падал на пути профиля с кириллицей и пробелами – профиль во временной папке. Закрыто.
- AutoCAD: `RPC_E_CALL_REJECTED` при старте и неверный код версии в `SaveAs` – повтор вызовов COM, сохранение
  в формате по умолчанию. Закрыто пробной печатью.
- В шрифте рисунков нет символа ∅ – заменён на Ø. Закрыто.
- Разрывы страниц пустыми абзацами давали пустые страницы – `page_break_before` у заголовков. Закрыто.
- Номера таблиц и рисунков в тексте были зашиты числами – берутся из счётчиков. Закрыто.
- Sol на повторной попытке возвращал только исправленные разделы, остальные пустыми – принятые разделы
  сохраняются, переписываются только отклонённые. Закрыто прогоном.
- Sol писал «4.0» вместо «4,0» – получает числа с запятой, проверка отклоняет точку. Закрыто: принятый текст V3
  проходит проверку.
- Содержание вставлялось между заголовком «Введение» и его текстом (пустая стр. 4). Закрыто прогоном.
- Проверка не находила заголовок «Спецификация оборудования» (ошибка шаблона). Закрыто прогоном.
- Разделы «Аннотация», «Характеристика объекта», «Заключение» из ответа Sol (прогон 22:13, попытка 4) были
  отклонены старой ошибкой проверки чисел (2700, 675) и не попали в `prose.json`; прогон 22:31 после исправления
  был прерван на вызове Sol. Ответ попытки 4 повторно проверен исправленным `check_prose`, принят и перенесён
  в `prose.json` (копия прежнего файла – `prose.before_merge.json`).
- Проверка записки принимала за заголовок строку текста («Гидравлический расчёт выполняется по методике…»),
  из-за чего ложно срабатывал «порядок разделов». Заголовком теперь считается строка с номером раздела или
  только название. Закрыто: старые V3/V4 по-прежнему бракуются, новая V3 – нет.

## Правила, которые нельзя ослаблять
- Пороги проверок задаёт только код в `check_*.py`, не исполнитель и не конфиг заказа.
- Исполнитель не вызывает проверки и не пишет «доказательства»; `cad.py` сам перезапускает `generate.py`
  и отклоняет результат, если Astra изменил `sheet_data.json` или файлы в `core/` и `tasks/`.
- Если проверка не прошла за отведённое число попыток, вариант останавливается с понятной причиной,
  а не уходит в бесконечный ремонт.
