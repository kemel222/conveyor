# Конвейер учебных инженерных работ

Конвейер строит пояснительную записку и CAD-листы по варианту задания. Расчёты и проверки выполняет код. Sol пишет только текст разделов. GPT-6 Astra пишет только генератор CAD-листов в отдельной рабочей папке.

## Этапы

| Этап | Исполнитель | Проверка |
|---|---|---|
| Чтение варианта и норм | `tasks/water_sprinkler/variants.py`, `norms.py` | тесты вариантов |
| Гидравлический расчёт | `hydraulics.py` | `tests/test_hydraulics.py` |
| Текст разделов | Sol через `core/llm.py` | `check_prose.py` |
| DOCX и PDF | `report.py`, `figures.py`, LibreOffice | `check_report.py` |
| CAD-листы | GPT-6 Astra через `codex exec` | `cad_check.py`, AutoCAD plot |
| Архив | `run.py` | ZIP и SHA-256 |

Исполнитель не запускает проверки и не подписывает результат. Конвейер сам запускает генератор, проверяет DXF и проверяет PDF после печати.

## Запуск

```text
cd conveyor
python -X utf8 run.py "<папка заказа>" --variants 3 4
python -X utf8 run.py "<папка заказа>" --variants 3 --only text
python -X utf8 run.py "<папка заказа>" --variants 3 --reuse
python -X utf8 -m unittest discover -s tests -t .
```

В папке заказа нужны DOCX хрестоматии и `order.json` с данными студента, группы, преподавателя и организации. Результат создаётся в `<заказ>/Выдача/Вариант_N/`. Журнал находится в `<заказ>/_conveyor/run.log`.

`--reuse` использует принятый текст и существующий генератор, но повторно запускает генератор и проверки.

## Время работы

| Участок | Обычно | Предел |
|---|---:|---:|
| Расчёт модели | секунды | секунды |
| Один вызов Sol | 2,5 до 7 мин | 15 мин |
| Текст варианта | 5 до 15 мин | до 60 мин, четыре попытки |
| Сборка DOCX и PDF | 1 до 3 мин | до 12 мин |
| Один раунд Astra | минуты | 30 мин, остановка после 8 мин без активности |
| CAD-итерации | 1 до 3 раундов | до 90 мин |
| Запуск генератора и проверка | секунды | 3 мин на раунд |
| Печать одного листа AutoCAD | секунды или минуты | 5 мин |
| Три листа AutoCAD | минуты | до 15 мин |
| ZIP и SHA-256 | секунды | обычно меньше минуты |

При нормальной работе один вариант занимает около 10 до 30 минут. Очередь модели, 503, повторные попытки и занятый AutoCAD могут увеличить время до нескольких часов.

## Рабочие ограничения

- Полный прогон реального заказа намеренно не выполняется. Для быстрой проверки используется `_scratch/astra_smoke`.
- Одновременные запуски одной папки заказа запрещены. Блокировки нет, поэтому файлы и журналы могут перезаписаться.
- При ошибке модели или проверок частичный CAD не выдаётся.
- Для выпуска нужен настоящий PDF-плот AutoCAD из того же DXF. Диагностический PNG не заменяет PDF.
- AutoCAD должен иметь `DWG To PDF.pc3`, формат A3 и доступный COM.
- Пути с пробелами и кириллицей поддерживаются, но LibreOffice и COM зависят от профиля Windows.
- Персональные данные не заполняются автоматически.
- Вариант 20 не поддерживается.

## Известные риски

1. `cad_check.py` пока не сверяет с моделью координаты оросителей, связность труб, спецификацию и таблицу гидравлики построчно.
2. Полный CAD-прогон и визуальный просмотр записки не выполнялись.
3. Коэффициент ширины текста `CHAR_W = 0.62` приблизительный.
4. Штамп проверяется формально и не сверялся с приложениями ГОСТ.
5. Расчётная схема записки не сверяется автоматически с таблицей участков.
6. В модели есть неподтверждённые допущения: тупиковый питающий трубопровод, стояк у торцевой стены, подключение 3 м, `Z` равна высоте помещения, скорость до 5 м/с и критерий выбора диаметра 20 процентов.
7. Каталог насосов и группы помещений требуют проверки по первоисточникам. Количества опор, тройников и отводов приблизительные.
8. Полный режим `--only cad` и параллельные запуски не проверялись.

## Проверки

Сейчас проходят 14 тестов. Smoke-DXF проходит `check_sheet`. Внешний CAD-запуск может завершиться ошибкой очереди Astra или ограничением сервиса. В таком случае конвейер останавливается и не выпускает частичный результат.

## Структура

- `core/` содержит общий запуск моделей, CAD-набор, печать и проверки.
- `tasks/water_sprinkler/` содержит расчёт, текст, отчёт и данные спринклерной задачи.
- `tests/` содержит офлайн-тесты.
- `_scratch/astra_smoke/` содержит изолированный тестовый DXF.
- `_trial/` не входит в поставочный архив.
